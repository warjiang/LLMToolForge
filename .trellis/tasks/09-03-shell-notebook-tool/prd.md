# Shell Notebook 实用工具

## Goal

为开发者提供一个比终端历史更易编辑、复用和整理的本地 Shell 指令工作区：用户可以像使用 notebook 一样按单元格编写、执行和调试 Shell 指令，并将最终指令导出为不含执行结果的 Markdown 文档。

## Confirmed Facts

- 功能入口位于现有“实用工具”页面，现有工具以可排序标签页组织。
- 应用是 Tauri 2 桌面应用；浏览器开发模式无法直接执行本机 Shell 指令。
- 后端已有 `run_sandboxed_command` 命令，但它服务于 AI Agent 的一次性受控执行，不适合作为本工具的执行入口。
- 后端已有登录 Shell `PATH` 恢复逻辑，可用于让桌面应用启动的 Bash 访问用户本机命令。
- 项目已有系统文件保存对话框和后端文本写入模式，可用于 Markdown 导出。
- 前端目前没有 Monaco、CodeMirror、Shiki、Prism 等代码编辑或语法高亮依赖。

## Requirements

- 提供由多个 Shell 代码单元格组成的可编辑工作区。
- 每个单元格支持 Bash 语法高亮，并可独立执行。
- 每次执行实时展示 stdout、stderr、退出状态、耗时和运行状态。
- 同一工作区使用真实的长驻 Shell 会话；变量、当前目录、函数、alias 和 shell option 等进程状态在后续执行中保留。
- shell option 采用真实 Bash 语义：`set -e` 等作为进程状态持久化；在启用 `set -e` 后执行失败命令会终止整个会话（忠实语义，不做隔离），前端标记会话失效、保留源码与已有输出并提供一键重启，且能区分“单元格失败”与“会话失效”。
- 会话以干净 Bash 启动（`--norc --noprofile`），不加载用户个人 rc；UI 需明确提示该行为。
- stdout 和 stderr 只作为产生它们的单元格输出展示，不自动注入变量或后续单元格。
- 后续执行可以读取 Shell 保留的上一命令退出状态。
- Shell 状态按实际执行顺序演进，与页面位置解耦；调整或重跑前序单元格不会自动重跑后续单元格。
- “全部运行”按当前页面顺序串行执行，遇到首个非零退出码立即停止队列；“重启会话”清空运行时 Shell 状态，但保留单元格源码。
- 单元格内容在执行后仍可继续编辑并重新执行。
- 支持新增、删除和调整单元格顺序，且不因输出内容变化导致布局跳动。
- 支持停止仍在运行的单元格；首版停止操作终止 Bash 及其子进程并自动重启会话，会清空变量、当前目录、函数和 alias 等运行时状态，但保留源码与已有输出。
- 首版不设置自动超时，持续运行的命令由用户显式停止。
- 首版不提供 stdin 输入、密码提示、PTY 或 TUI 交互；等待输入的命令会保持运行，直到用户停止。
- Bash 以当前桌面用户权限直接作用于本机环境，不接入 AI Agent 的沙箱模式、审批或命令白名单。
- 未选择工作目录时以用户主目录 `$HOME` 作为会话启动目录。
- 用户可选择新的启动目录；切换启动目录会重启 Bash 会话。
- 单元格内执行 `cd` 会更新当前 Shell 目录，但不会改写配置的启动目录；重启会话后回到启动目录。
- 单元格源码、顺序和启动目录自动保存到本机，应用重启后恢复。
- 执行输出、退出码和 Shell 运行时状态不持久化，所有 Shell Notebook 数据均不参与云同步。
- 支持将当前全部指令导出为 Markdown；每个非空单元格输出为独立的 `shell` fenced code block，不包含执行结果。
- 命令只在用户明确触发执行时运行，不因打开页面、恢复草稿或编辑内容自动执行。
- 桌面端执行失败时返回可区分的结构化状态，前端不得只显示通用错误。
- 中文和英文 UI 文案均需完整。

## Initial Scope Boundaries

- 首版面向本机非交互式 Shell 指令，不包含 SSH 远程执行。
- 首版固定使用 Bash，不自动切换到 Zsh、PowerShell 或 CMD；Windows 未安装可解析的 Bash 时明确提示不可用。
- 首版导出 Markdown，不定义可重新导入的 notebook 文件格式。
- 首版不包含富文本说明单元格、图表输出或协作共享。
- 首版不承诺后台作业跨单元格存活或准确归属延迟输出；需要观察输出的命令应以前台方式运行。
- 不将命令、输出或可能包含密钥的环境状态纳入云同步，除非后续明确改变范围。
- 首版不提供 Agent 沙箱或执行审批；本工具与用户在本地终端主动执行命令具有相同信任模型。

## Acceptance Criteria

- [ ] 用户可以创建多个 Shell 单元格，编辑、排序、删除并逐个执行。
- [ ] 同一 Shell 会话中的后续执行能够访问前序执行产生的变量、当前目录、函数、alias 和 shell option。
- [ ] stdout 和 stderr 只显示在对应单元格，不会自动写入环境变量。
- [ ] 状态按实际执行顺序演进；“全部运行”按页面顺序执行，“重启会话”不会删除源码。
- [ ] “全部运行”遇到首个非零退出码停止，失败单元格之后的队列项保持未执行。
- [ ] 每个单元格能区分等待、运行、成功、失败、已取消和会话失效状态。
- [ ] 启用 `set -e` 后执行失败命令会终止整个会话（忠实 Bash 语义），会话标记为失效并保留源码与已有输出，提供一键重启；UI 明确区分“单元格失败”与“会话失效”。
- [ ] stdout 与 stderr 可查看，非零退出码不会被误报为执行成功。
- [ ] 长时间运行的命令持续流式输出且不会自动超时；用户可通过停止操作终止。
- [ ] 单次运行输出超过上限时截断并显示明确的截断状态，同时后端继续排空管道，命令不因输出满而卡死。
- [ ] 首版不会向运行中命令提供 stdin；等待输入的命令可被停止并触发会话重启。
- [ ] 用户可以停止运行中的命令；Bash 及其子进程均被终止，随后会话自动重启，UI 明确显示运行时状态已重置，源码和已有输出不丢失。
- [ ] 停止、页面卸载和应用退出后不残留 Bash 子进程或临时脚本文件；崩溃遗留的临时文件在下次启动被清理。
- [ ] 命令以当前桌面用户权限在所选工作目录中直接执行，不经过 Agent 沙箱或审批流程。
- [ ] 未选择目录时 Bash 从 `$HOME` 启动；执行 `cd` 后 UI 显示实际当前目录，重启后回到配置的启动目录。
- [ ] 会话以干净 Bash 启动（`--norc --noprofile`），不加载用户个人 rc；UI 明确提示该行为。
- [ ] 应用重启后恢复单元格源码、顺序和启动目录，但不恢复输出、退出码或 Shell 状态。
- [ ] 应用重启恢复草稿后明确展示“会话未启动、结果已过期”状态，不把历史单元格误呈现为可用运行结果。
- [ ] Shell Notebook 草稿和输出不注册到云同步资源。
- [ ] Markdown 导出只包含按当前顺序排列的非空 Shell 代码块，不包含输出或运行元数据。
- [ ] 未经用户点击执行的单元格不会运行。
- [ ] 功能在支持的桌面平台上通过前后端契约测试和关键交互测试。
- [ ] 浏览器开发模式明确展示桌面端限制，不产生无意义的执行请求。
- [ ] 首版所有平台均使用 Bash 语义；找不到 Bash 时返回可识别错误，不回退到其他 Shell。
